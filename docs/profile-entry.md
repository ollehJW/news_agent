# 누락된 계정 정보와 서비스 진입

WiaNews와 WiaCoding의 계정 조회는 팀·직급·조직에 LEFT JOIN을 사용합니다. 소속이 NULL이어도 유효한 통합 세션은 `/api/auth/me`에서 200으로 응답합니다. 인증 실패(401)와 프로필 정보 누락은 구분합니다.

사용자 응답에는 `organization`과 `missing_profile_fields`를 제공합니다. 이름·조직·팀·직급·이메일의 NULL, 공백, `미지정`을 플랫폼 입력 팝업과 동일하게 판정합니다. 프론트엔드는 일반 사용자의 누락 정보를 감지하면 `/login?profile=complete&next=...`로 이동합니다. 원래 서비스의 경로·쿼리·해시를 보존하며 세션을 재발급하지 않습니다. 기존 직접 접속 URL의 플랫폼 서비스 경로 변환 로직을 유지합니다.

관리자는 소속 정보 입력 없이 기존 관리자 화면에 접근합니다. 초기 비밀번호 변경은 프로필 입력보다 우선합니다. 비활성·만료·없는 세션은 기존처럼 로그인 대상입니다.

플랫폼에서 누락 정보를 입력하고 완료를 확인하면 원래 서비스로 돌아갑니다. 누락 정보가 남은 상태에서 WiaNews·WiaCoding 진입 팝업을 취소하면 플랫폼 홈으로 복귀하여 반복 리디렉션을 피합니다. 비밀번호 초기화 방식과 WiaMeet·WiaReport 동작은 변경하지 않았습니다.

검증: 런타임 환경 및 AX_SERVICE_CONFIG를 설정한 뒤 `AX_RUN_DB_TESTS=1 .venv/bin/python backend/tests/test_profile_entry.py`. 실제 PostgreSQL을 사용하는 임시 데이터는 모두 롤백합니다. 브라우저에서는 두 서비스의 `/agent` 직접 진입, 이전 팝업 닫기 기록이 있는 경우, 취소·홈 이동, 저장·원래 URL 복귀, 동일 세션 유지, 새로고침, 관리자 예외 및 미로그인 이동을 확인했습니다.
