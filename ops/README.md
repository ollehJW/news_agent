# WiaNews 운영

- 접속 주소: https://dev-axforwork.wia.co.kr/wianews/ (AX for Works 게이트웨이)
- 기존 주소: https://dev-axforwork.wia.co.kr:9802 (계속 사용 가능)
- 프론트엔드: 빌드된 React 파일을 HTTPS 9802 포트로 제공하고 `/api` 요청을 백엔드로 전달합니다. 스트리밍 응답도 그대로 전달합니다.
- 백엔드: `127.0.0.1:9801`. 외부에서는 프론트엔드의 HTTPS 주소로 API를 사용합니다.
- `wia` 사용자 systemd 서비스입니다. linger가 활성화되어 로그아웃 이후와 재부팅 후에도 실행됩니다. 프로세스 종료 시 5초 후 다시 시작합니다.

## 상태와 로그

```bash
systemctl --user status wianews-backend wianews-frontend
journalctl --user -u wianews-backend -u wianews-frontend -f
```

## 변경 반영

프로젝트 루트(`/home/wia/projects/wianews`)에서 실행합니다.

```bash
# 프론트엔드 변경
npm run build --prefix frontend
systemctl --user restart wianews-frontend

# 백엔드 코드 또는 .env 변경
systemctl --user restart wianews-backend
```

백엔드는 루트 `.env`를 읽습니다. 구독 스케줄러 중복 실행을 방지하기 위해 worker는 1개로 유지합니다. 서비스 실행 중 별도 개발용 백엔드를 동시에 실행하지 않습니다.

## 서비스 설정

`~/.config/systemd/user/wianews-*.service`는 이 폴더의 `systemd/` 설정 파일을 참조합니다. 설정 수정 후 적용합니다.

```bash
systemctl --user daemon-reload
systemctl --user restart wianews-backend wianews-frontend
```

## HTTPS 인증서

- 인증서: `/home/wia/.local/share/wianews/tls/fullchain.pem`
- 개인 키: `/home/wia/.local/share/wianews/tls/privkey.pem`
- 설치한 인증서 만료: 2027-01-23 23:59:59 UTC

인증서와 키는 Git에 저장하지 않습니다. 갱신한 파일로 교체하고 프론트엔드 서비스를 재시작합니다. 파일 권한은 600, 디렉터리는 700으로 유지합니다.

## 관리자 운영·토큰 대시보드

관리자 로그인 시 계정 관리, 운영 관리, 토큰 관리 메뉴를 제공합니다.
`/api/admin/operations`, `/api/admin/tokens`, `/api/admin/llm-pricing`은 관리자 권한을 검사합니다.
조회 기간은 한국 시간 기준 양 끝 날짜를 포함하며 최대 366일입니다.

- 운영 관리: 현재 계정·저장된 샘플·활성 구독·수신 멤버 수, 기간 내 샘플/수집/발행 작업 상태,
  수신자별 메일 결과, 사용자별 활동, 최근 오류 100건.
- 최근 로그인은 마지막 로그인 시각이며, 로그인 횟수나 접속 이력 통계가 아닙니다.
- 토큰 관리: 일별/사용자별/단계별/모델별 집계, 조건 필터, 호출 기록 50건 단위 조회.
- `llm_pricing`은 `(provider, model)`별 100만 토큰당 USD 입력/캐시 입력/출력 단가와 변경 시각을 저장합니다.
  실제 계약 단가를 관리자가 입력해야 합니다. 기본 단가는 없습니다.
- 비용은 저장된 현재 단가로 과거 조회 기간도 다시 계산하는 추정치입니다. 청구 이력이 아닙니다.
  입력에서 캐시 입력을 빼고 각각의 단가를 적용합니다. 캐시 기록이 없으면 일반 입력 단가를 적용합니다.
  단가 미설정 또는 입출력 토큰 누락 호출은 비용 합계에서 제외하고 제외 건수를 표시합니다.
- 호출 종료 기록은 성공을 보장하지 않습니다. 연결된 오류가 있으면 별도 표시합니다.

### 활성 구독 관리와 구독별 사용량

- 관리자 **구독 관리**에서 활성 구독을 검색하고 사내·사외 수신 멤버를 추가/삭제하거나 수신 상태를 변경합니다.
  멤버 0명 저장은 구독 자체를 취소하지 않으며 기존 발행 이력도 유지합니다.
- 발행 주기/요일/매월 발행일/시작일/구독 이름은 선택한 구독에만 적용합니다. 발행 시간은 08:00 KST입니다.
- 쿼리(최대 5개), 도메인 및 전체 도메인 검색은 샘플 단위 공유 설정입니다. 같은 샘플의 모든 구독에 적용합니다.
  원본 샘플 HTML과 기존 기사·발행본은 수정하지 않습니다. 기존 수집 이력을 재실행하지 않습니다.
- 변경은 트랜잭션과 revision 검사로 동시 편집 충돌을 방지합니다. 관련 수집/발행 작업이 진행 중이면 조건 저장을 거절합니다.
- 발행 히스토리는 전달된 발행본과 자동 작업 결과를 각각 50건씩 조회하며, 해당 구독의 발행본만 미리볼 수 있습니다.
- `subscription_llm_requests(request_id, sample_id)`는 구독용 LLM 호출의 공유 샘플을 기록합니다.
  수집 전처리·평가·발행 시점에 기록하므로 이후 실패한 호출도 연결됩니다. 샘플 생성 비용은 여기에 포함하지 않습니다.
- 과거 기록은 수집/기사/발행본에 남은 요청 ID로 샘플을 하나로 확정할 수 있을 때만 보완합니다.
  출처가 불명확한 호출을 사용자의 다른 구독으로 추측해서 배정하지 않습니다.
- 토큰 관리의 활성 구독별 행/필터는 해당 샘플의 공통 운영 호출을 표시합니다.
  동일 샘플의 구독 간 사용량은 겹칠 수 있으므로 행을 합산하지 않습니다. 전체 합계에서는 호출 ID당 한 번만 집계합니다.

### Exa Search 뉴스 건수

토큰 관리 첫 번째 카드는 Exa가 반환한 기사 수(중복·전처리 제외 전)를 표시합니다.
기간·사용자·활성 구독 필터를 적용하며, LLM 모델/처리 단계 필터는 적용하지 않습니다.
`exa_search_usage`에 성공한 검색 응답별 건수와 사용자/샘플/구독 수집 구분을 저장합니다.
여러 쿼리 중 일부가 실패하더라도 이미 성공한 검색 건수는 유지합니다. 같은 샘플을 공유하는
구독의 검색량은 전체 합계에서 중복 계산하지 않습니다. 과거 구독 실행은 저장된
`search_results`로 보완하고, 원본 검색량이 저장되지 않았던 과거 샘플 실행은 추정하지 않습니다.
뉴스 건수는 검색 API 호출 수나 Exa 청구 금액을 의미하지 않습니다.

### 구독 피드백 및 결과 메일

- 내 구독의 피드백 작성은 구독 개설자와 사내 수신 멤버에게 허용합니다. 해지된 구독이나 타인의 구독에는 요청할 수 없습니다.
- `subscription_feedback`에 요청자·이메일·구독/주제·수집 조건 스냅샷·요청 본문·상태·관리자 답변과 알림 이력을 저장합니다.
  상태는 `pending`(검토 대기), `held`(보류), `completed`(반영)입니다. 보류 후 반영이 가능합니다.
- 관리자 피드백 관리에서 처리 내용/보류 이유를 입력하고 저장하면 요청 시 기록한 요청자 이메일 한 곳에 결과를 전송합니다.
  반영 팝업에서 최신 쿼리·도메인을 불러와 편집합니다. 조건 저장과 피드백 반영/메일 발송 예약은 하나의 트랜잭션으로 처리합니다.
  구독 일정·이름·멤버는 유지하며, 동일 샘플의 공유 수집 조건에 적용합니다. 변경 전후 조건은 알림 이력에 보관합니다.
  구독 설정 revision 충돌 또는 수집·발행 중 변경 제한에 걸리면 조건과 피드백을 모두 변경하지 않고 메일도 발송하지 않습니다.
- `backend/template/feedback_result.html`은 현대위아 뉴스레터 디자인의 800px 테이블 기반 이메일 템플릿입니다.
  사용자 본문은 자동 HTML 이스케이프하고, 뉴스레터 변환기를 거치지 않는 전용 HTML로 발송합니다.
- 요청/처리 ID와 revision으로 중복 접수·동시 처리·동일 처리 메일 중복 발송을 방지합니다.
  메일 처리 상태는 `processing`, `sent`, `failed`, `unknown`으로 남깁니다.
  실패가 확인된 최신 결과만 관리자 재발송 버튼을 제공합니다. 결과 불명은 자동 재발송하지 않습니다.
  프로세스 재시작 시 중단된 `processing` 알림은 `unknown`으로 표시합니다.
- `sent`는 SMTP 서버 수락 기준이며, 수신함 도착이나 열람을 보장하지 않습니다.

## 서비스 소개 페이지

소개 페이지는 `https://dev-axforwork.wia.co.kr/wianews/`이며, 서비스 페이지는 `https://dev-axforwork.wia.co.kr/wianews/agent`입니다. 시작하기 링크에서 서비스 화면을 엽니다. 로그인하지 않았다면 서비스 주소에서 로그인 화면이 표시됩니다. 기존 `/wianews/#app` 북마크는 `/wianews/agent`로 자동 전환됩니다. 기존 9802 포트에서도 `/`는 소개, `/agent`는 서비스 화면입니다.

소개 영상과 PPT가 준비되면 `frontend/public/media/wianews-intro.mp4`, `frontend/public/guides/wianews-guide.pptx` 등에 파일을 넣고 `frontend/src/introContent.js`의 `videoUrl`, `guideUrl`을 각각 `/media/wianews-intro.mp4`, `/guides/wianews-guide.pptx`로 설정합니다. `npm run build --prefix frontend`로 배포하면 영상 재생 및 PPT 다운로드가 활성화됩니다. URL이 `null`인 동안에는 준비 중 상태를 표시합니다. 소개 자료는 로그인 없이 접근할 수 있으므로 공개 가능한 자료를 등록합니다.

## AX for Works 하위 경로

포털이 `/wianews/` 요청을 이 서비스의 9802 포트로 전달합니다.
프론트엔드는 상대 자산 경로와 `src/serviceUrl.js`를 사용해 `/wianews/api`, `/wianews/media` 요청을 생성합니다.
기존 포트의 루트 주소에서는 기존 `/api`, `/media` 경로를 사용합니다.
게이트웨이가 로그인 쿠키 경로를 보정하므로 새 주소에서는 다시 로그인합니다.
일반 프론트엔드 빌드/배포 절차는 동일합니다.

게이트웨이 대상 주소·경로는 `../ax_for_works/config/config.yaml`에서 관리하며 저장 후 자동 반영됩니다.
